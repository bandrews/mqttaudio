remains the 2.0 release line until field testing accepts this candidate.

## Conflict decisions

- Keep the v2.1 real-time engine, typed input/output formats, per-frame ducking,
  off-thread command preparation, memory limits, windowed streaming, and
  progressive disk decoding. Port fixes into these paths instead of restoring
  the older mixer/control implementation.
- Keep main's gain range of 0–4, including input/voice/sample gains and calibration,
  together with v2.1's configurable limiter ceiling. Tests assert the configured
  ceiling rather than the old hard clip at digital full scale.
- Keep channel aliases for routing and support channel display labels in volume
  settings. Both are editable in the configuration editor.
- Use exact ALSA PCM identifiers for discovery/selection; preserve friendly names
  on other platforms. Skip the ALSA null sink in device discovery/selection.
- Share physical capture only for matching device, latency, requested channel
  count and requested rate. Logical strips keep independent routes and levels.
  Capture requests compatible duplex buffer sizes and supported native formats,
  retains drift correction, and respects the selected resampling quality.
- Activity-triggered ducking observes each strip's routed source channels.
  Applied state and health cross to HTTP through snapshots/atomics.
- CPAL-recovered xruns and device reroutes keep their stream; permanent output
  errors trigger the existing supervisor. Input USB reconnection remains a field
  limitation noted below.
- File/network preparation is bounded and runs outside command dispatch. Stops
  cancel pending work, abandoned stream producers are stopped, and responses
  report command errors/cancellation. Pending full decodes reserve memory before
  another full load is admitted.
- Preserve cache disablement, HTTP persistence/revalidation, corruption recovery,
  safe invalidation, pitch-loop continuity, volume ramps, authentication,
  environment configuration, and the configured MQTT reconnect delay.
- Tests from main that assumed synchronous disk decoding now await the progressive
  buffer before asserting content, persistence, corruption recovery or freshness.
  No test assertions about those outcomes were removed.

The live meter test exposed a decoder-lock race that created empty channel maps.
A deterministic contention test now covers creation-time metadata reads, and the
live output meters pass. Another regression covers a progressive decode that
finishes before dispatch: it still receives the buffer promotion needed for pitch
correction.

The benchmark fixture writer now buffers its WAV output, avoiding millions of
single-sample filesystem writes during validation. The web build retains Vite's
bundle-size advisory (approximately 532 kB before gzip); this is not a build error.
Proxy disconnect messages are expected when the live browser suite deliberately
kills/restarts the daemon and verifies reconnection.

Docker Desktop's filesystem became read-only during a rebuild. After an approved
restart, the Memoria development containers and build worker were restored. Only
this task's generated crate build cache was cleaned, and the complete Linux
validation was rerun successfully. No application data volumes were removed.

Linux software-PCM tests do not establish physical multichannel USB behavior.
Windows/WASAPI hardware was not available in this environment.

## Field release checklist

- Use the venue configuration on the target Linux host and copy identifiers from
  `--list-devices` / `--list-inputs`.
- Check every speaker and microphone route, including multiple logical strips on
  one multichannel interface, independently controlled volume/mute, and gains
  above unity at safe physical output levels.
- Confirm duplex operation at the required channel count, sample rate and buffer
  size, and run a sustained microphone + music + effects session.
- Check activity-based ducking and talkback acquire/renew/release/expiry with the
  actual gateway/client. Confirm no unwanted microphone audio on lost ownership.
- Test disconnect/reconnect behavior. Output has supervised recovery; a lost input
  currently requires a daemon restart after reconnection. Physical USB unplug and
  platform-driver recovery are not established by container tests.
- Verify the deployed reverse proxy, TLS/authentication, and client reconnection.
- After acceptance, merge v2.1 into main and finalize the stable version. This
  integration does not publish a stable release or change main.
